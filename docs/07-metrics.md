## 一、新能源环境指数


产品最核心的派生指标，首页、地图底部面板、站点详情、AI 报告都在用。


### 1.1 定义

```
环境指数 = 今日预测发电量 / 今日理想发电量 × 100
```

**不是四个因子的加权求和，而是物理出力比。**

含义直白：今天能发出这个站点潜力的百分之多少。


### 1.2 为什么不用加权求和

早期版本用「辐射 50% + 云量 25% + 温度 15% + 风速 10%」的加权评分，
有三个结构性缺陷：

| 缺陷 | 说明 |
| --- | --- |
| **共线性** | 云量高 → 辐射低，两个因子描述的是同一件事。加权求和等于把「云」算了两遍，实际权重达 75% |
| **补偿性** | 加权和允许互补：夜间辐射为 0，靠温度和风速仍能拿到 25 分；风电站风速低于切入风速出力为 0，却因温度良好得分 —— 与物理事实矛盾 |
| **权重无依据** | 50/25/15/10 是拍出来的，无法验证，也无法解释为什么不是别的数 |

物理出力比同时解决三者：

- 云的影响已包含在辐射预测里，不重复计入
- 出力为 0 时指数自然为 0，无法被补偿
- 各因子的影响由物理模型决定，不需要人工定权重
- 与 §二 的发电量估算**共用同一套模型**，一份实现、一份口径


### 1.3 光伏指数

```
指数 = E_actual / E_ideal × 100

E_actual = 实际气象条件下的日发电量
E_ideal  = 晴空辐射 + 25℃ 标准温度下的日发电量
```

两者跑**同一个 pvlib 模型链**，只换输入：

| | 辐射 | 气温 | 风速 |
| --- | --- | --- | --- |
| `E_actual` | 预报 GTI | 预报气温 | 预报风速 |
| `E_ideal` | 晴空 GTI | 25℃ | 1 m/s（参考值） |

分子分母的时间口径必须一致：Open-Meteo 的小时辐射是**前一小时平均值**（标在区间末），
晴空基准也取同一区间的小时均值，太阳位置取区间中点（见 §2.1）。
分母用整点瞬时值会让晴天的指数到不了 100，逐时曲线在日出日落两端也会错。

四个气象因子全部通过物理模型进入，不需要任何权重：

```
辐射  →  直接决定 POA 辐照
云量  →  已体现在辐射预报中，不单独计入
温度  →  经电池温度模型影响功率温度系数
风速  →  经电池温度模型影响散热
```

这个量在光伏行业里就是**相对晴空出力比**，与性能比（PR）同源，
不是自创指标，可与 PVGIS、Global Solar Atlas 的输出对照验证。


### 1.4 风电指数

风电没有「晴空」这样的物理上界 —— 额定风速以上满发，
但满发不是常态，拿满发做分母会让所有站长期低分。

改用**容量因子分档映射**：

```
CF = 今日预测发电量 / (装机容量 × 24h)
```

| CF | 指数 | 等级 |
| --- | --- | --- |
| ≥ 0.38 | 90 – 100 | 优秀 |
| 0.22 – 0.38 | 70 – 89 | 良好 |
| 0.10 – 0.22 | 55 – 69 | 一般 |
| < 0.10 | < 55 | 较差 |

分段线性插值，断点 CF = 0 / 0.10 / 0.22 / 0.38 / 0.55 对应 0 / 55 / 70 / 90 / 100 分。

阈值依据（2026-09 校准，见 §八）：日容量因子是双峰分布——静风日与大风日各占一头，
0.22 ≈ 国内陆上风电年均容量因子，落在「良好」下沿；按此断点 5 个风电基地一年的分档为
优/良/中/差 ≈ 29 / 11 / 20 / 40%，不再一边倒。可配置。

2026-09-15 目录风电改按投运年份选机型档（§2.2）后重跑：5 个基地年 CF 升到 0.32–0.61，分档变为
49 / 14 / 19 / 18%。**断点不动**：REIT 公告的 9 座风电场 49 个场站年，实际年 CF 中位 0.275
（P10 0.23、P90 0.38；加回限电中位 0.28），真实场站的年均落在「良好」区间，与断点的物理锚点一致；
基地是风资源好的样本，「优秀」日多是实情。若按旧分布的分位数平移，断点会变成 0.21 / 0.41 / 0.63 / 0.79，
典型场站的年均只能得「一般」，反而失真。

> 光伏与风电的分数不严格可比 —— 归一化基准不同。
> 这在产品上无影响：用户看的是自己站点的相对好坏，不是跨类型排名。
> 但**不要**把两类站点的指数放在同一个排行榜里。


### 1.5 分档阈值

| 分数 | 等级 | 颜色 |
| --- | --- | --- |
| ≥ 85 | 优秀 | Energy Green |
| 70 – 84 | 良好 | Energy Green |
| 55 – 69 | 一般 | Warning Orange |
| < 55 | 较差 | Danger Red |


### 1.6 因子归因

指数不再是加权和，但用户点「?」仍需知道为什么是这个分。
改用**归因**而非权重 —— 逐项关闭偏离因素，看指数回升多少：

```
今日 82 分

辐射条件    云层使辐照降至晴空的 64%      −33 分
温度损失    32℃ 高温使组件效率下降        −6 分
散热增益    4.5 m/s 风速改善散热          +1 分
```

计算方式：把该因子替换为理想值重算指数，差值即该因子的贡献。

归因比权重更有说服力（它是算出来的，不是定义的），
也是 [08 文档](./08-ai-design.md) 中 AI 报告的直接输入。

接口返回见 [06 §十二](./06-api-contract.md) 的 `EnergyIndex.factors`。


### 1.7 计算周期

指数按**当日**计算，不是瞬时值。

产品语义是「今日适宜发电」，用户全天看到的应是同一个分数；
用瞬时值会导致傍晚分数暴跌，与文案矛盾。

刷新时机：每日 00:00 生成，气象预报更新后（每 1 小时）重算。


#### 日间时段

**日间时段不是固定的 06:00–18:00，按站点经纬度与日期计算日出日落。**

固定时段在高纬度和冬季会严重失真：漠河冬至日照不足 7 小时，
用 06:00–18:00 求平均会把 5 小时的夜间数据算进去。

```
日间时段 = [日出时刻, 日落时刻]
```

计算见 [附录 A](#附录-a太阳位置计算)。

> 注意区分两个时间概念：
> 本节的**日间时段**是计算窗口，按日出日落动态计算；
> AI 报告的**上午 / 下午 / 晚间**（06–12 / 12–18 / 18–24）是面向用户的固定展示分段，
> 不随日出日落变化。两者用途不同，不要混用。


### 1.8 分数分布与校准

物理出力比的取值不会均匀铺满 0–100，需要在真实数据上校准分档阈值。

上线前的校准方法：

```
取 5 个不同气候区的样本站点
拉过去 365 天的历史气象（Open-Meteo archive API）
逐日跑一遍指数
看分数分布
```

检查两件事：

| 检查 | 期望 |
| --- | --- |
| 分布是否过度集中 | 不应大部分日子挤在同一档 |
| 分档是否符合直觉 | 抽查若干日期，人工判断晴天/阴天与档位是否吻合 |

若分布不合理，调整 1.5 的分档阈值，**不要去改指数定义** ——
定义有物理意义，阈值只是展示分档。

> 这一步不能省。指数是产品第一眼看到的数字，
> 分布不合理会直接毁掉信任感（比如全年 90% 的日子都显示「良好」）。

## 二、发电量估算


V1 站点无实测数据，全部由气象数据推算。
接入实测后本章仅用于「预测值」，实测优先。

同时是 §一 环境指数的计算基础 —— 两者共用同一套实现。


### 2.1 光伏：pvlib 模型链

不要手写公式。用 pvlib 的标准链路：

```
1. 太阳位置        solarposition.get_solarposition(time − 30 min, lat, lon)   ← 区间中点
2. 晴空辐射        location.Location(...).get_clearsky(...) 取小时均值   ← 算 E_ideal 用
3. 倾斜面辐照      irradiance.get_total_irradiance(
                       surface_tilt, surface_azimuth,
                       solar_zenith, solar_azimuth,
                       dni, ghi, dhi, dni_extra, airmass,
                       model="perez")                             → POA
4. 电池温度        temperature.sapm_cell(poa_global, temp_air,
                       wind_speed, **TEMPERATURE_MODEL_PARAMETERS[...])
5. 直流出力        pvsystem.pvwatts_dc(g_poa_effective=poa,
                       temp_cell=..., pdc0=capacity × dc_ac_ratio, gamma_pdc=-0.004)
6. 系统损失        × (1 − losses)
7. 交流限幅        min(·, capacity)            逆变器按交流额定容量限幅
8. 日发电量        逐小时求和
```

**用 PVWatts 模型（第 5 步）是关键决定**：
它是 NREL 的标准简化模型，只需要装机容量与温度系数，
不需要组件型号、串并联结构等详细参数 —— 正好匹配「用户只填装机容量」这个输入约束。

**时间口径（第 1、2 步）**：Open-Meteo 的小时辐射是前一小时的平均值，标在区间末
（13:00 的值对应 12:00–13:00）。太阳位置要按区间中点 12:30 算，晴空基准也取同一区间均值。
按整点算时日电量只差 1%，但逐时曲线在日出小时偏高 30–70%、日落小时偏低 40–90%。

**当前功率取哪一格**：光伏出力是区间均值量，取**包含当前时刻**的区间末标签
（06:30 → 07:00，即 06:00–07:00 那一格）；风电出力来自瞬时风速，取**当前整点**。
两者口径不同，不能统一。取错一格在日出日落前后差几倍 —— 北京夏至 06:30 是
19 kW 与 84 kW 之别，19:30 是 40 kW 与 5 kW 之别。首页实时辐射、云层预警的
当前晴空指数 `kt_now`、逐日累积表的 `current_kw` 都按这条走，
字段的两种时间语义见 [04 §二](./04-data-specification.md)。
23:00–24:00 的区间末标签落在次日 00:00（今日帧外），退到当日最后一格 ——
那一小时光伏出力必为 0，不该显示成「数据获取中」。

**容量口径（第 5、7 步）**：站点容量是交流侧（[04 §七](./04-data-specification.md)，
目录数据集与用户自填口径一致），而 PVWatts 的 `pdc0` 是直流侧峰值功率。
直流侧按容配比换算，交流出力按额定容量限幅；把交流容量直接当 `pdc0` 会系统性低估 10–25%。

| 参数 | 含义 | 默认值 |
| --- | --- | --- |
| `capacity` | 交流侧额定容量（kW） | 站点配置 |
| `dc_ac_ratio` | 容配比，`pdc0 = capacity × dc_ac_ratio` | 1.2（国内地面电站典型 1.1–1.3） |
| `gamma_pdc` | 功率温度系数（/℃） | −0.004 |
| `losses` | 系统总损失，**含逆变器损耗**（与 PVGIS 的 14% 同口径，不再单独乘逆变效率） | 0.14 |
| 温度模型 | SAPM 参数集 | `open_rack_glass_glass` |
| 散射模型 | 天空散射到倾斜面 | `perez`。各向同性模型在晴朗干旱区低估 3–5%（缺环日分量），校准后换 Perez，见 §八 |

风速经第 4 步进入电池温度，因此散热效应是物理建模的，不是加权项。

**目录光伏的交直流未知（2026-09-17 实测，待定口径）**：`prediction_basis.catalog_basis`
要求每个光伏分期声明 `capacity_rating`，未声明就返回「光伏交流/直流容量类型未知，
暂不估算」—— 刻意不猜。生产库实测：

| 项 | 数量 |
| --- | --- |
| 光伏电站 | 13,472 |
| **含 unknown 分期、因此被挡住的** | **9,493（70.5%）** |
| 分期级 `dc` | 2,706 |
| 分期级 `ac` | 1,090 |
| 分期级 `unknown` | 9,822 |

unknown 的 `capacity_rating_raw` **全部**是我们导入时的兜底串 `'unknown'`，
即 GEM 那一列本身是空的，不存在「没映射到的值」可以补救
（映射见 `app/catalog/importer.py`：`MWac`→ac，`MWp/DC`/`MWdc`/`MWp`→dc）。

**已定为按直流解释**（2026-09-17）。理由：GEM 明确写了口径的那 3,796 个分期里
**71% 是 dc**，跟着数据源自己的分布走；且按 dc 解释得到的交流出力更保守
（`ac = cap / 1.2`，比按 ac 解释低约两成）。

落地方式：`catalog_basis` 返回三元组 `(容量, 不可估算原因, 是否用了直流假设)`，
第三项为 True 时 `capacity_note` 改成「数据源未声明交流/直流，按直流侧估算」，
不能和已声明口径的站点混在一起看。**只对「口径未声明」生效** ——
容量本身缺失、非光伏技术、省级占位坐标仍然拒绝估算。

计算口径随之从 `修订3` 升到 `修订4`，全目录快照与曲线缓存按版本失效，会重算一轮。
可估算的公开电站从 8,218 座升到约 17,700 座，全目录汇总电量会明显跳一档 ——
**那不是模型变准了，是口径假设变了**，对外解读要带上这句。

**安装方式与双面（2026-09-12）**：站点可选 `mounting`（`fixed` / `single_axis`）与 `bifacial`。
单轴跟踪用 `pvlib.tracking.singleaxis` 逐时刻求支架姿态：南北向水平轴、最大转角 60°、
含背轨、行间距比 `gcr` 0.35；此时倾角与方位角不生效。双面用 `pvlib.bifacial.infinite_sheds`
把背面辐照按双面率折进 `poa_global`，几何按行宽归一化（行距 1/gcr、离地 0.6），双面率 0.7、
地面反射率 0.2。理想值（指数分母）用同一套安装方式算，跟踪站的指数不会因此超过 100。
两者都未用实测校准，跟踪增益量级 15–25%、双面 5–12%，与行业经验一致；参数在 settings 里。

指数、日发电、当前功率、发电预测曲线、区域汇总**共用同一条链路**（`metrics/pv.hourly_power`），
不允许再各写一份。


### 2.2 风电：功率曲线

风电没有 pvlib 级别的标准库。`windpowerlib` 可用但需指定机型，
V1 用户不填机型，因此用通用功率曲线：

```
v_hub  = 各高度层（10 / 80 / 100 / 120 / 200 m）按对数廓线插值到轮毂高度
         风速对 ln z 线性；模型没有 200 m（GFS）且轮毂高于 120 m 时用最高两层的斜率外推
         只有 10 m 一层时降级：v_hub = v_10 × (h_hub / 10) ^ α，α = 0.18

v < v_in  或  v > v_out        P = 0
v_in ≤ v < v_rated             P = C × (v³ − v_in³) / (v_rated³ − v_in³)
v_rated ≤ v ≤ v_out            P = C

场站净出力 = P × (1 − losses)
```

**空气密度修正（2026-09-12）**：功率曲线是按标称密度 1.225 kg/m³ 给的。轮毂高度密度按
`ρ = p / (R T)` 逐时算（`surface_pressure` 与 `temperature_2m`），缺气压按海拔 ISA 换算，
海拔取 Open-Meteo 响应里的 `elevation`（90 m DEM），连海拔都没有才用标称值。修正按 IEC
61400-12-1 的变桨机组做法：`v' = v (ρ / ρ0)^(1/3)`，再查标称曲线，额定以上不受影响。
3000 m 海拔 ρ ≈ 0.85–0.9，不修正会把额定以下的出力高估两到三成。

**机型档与自定义曲线**：`turbine_class` 取 `generic` / `low_wind` / `medium_wind` /
`high_wind` / `custom`。前四档共用上面的三次方爬坡形状，只换切入 / 额定 / 切出：

| 档 | 切入 | 额定 | 切出 |
| --- | --- | --- | --- |
| `generic` | 3 | 12 | 25 |
| `low_wind` 低风速（大叶轮、低比功率） | 2.5 | 9.5 | 22 |
| `medium_wind` | 3 | 11 | 25 |
| `high_wind` | 3.5 | 12.5 | 25 |

`custom` 给 `power_curve`：`[{v, p}]`，`v` 递增、`p` 为额定容量的百分比，至少 3 点，
按线性插值取值，首点之前为 0、末点之后视作切出为 0。场站损耗仍按 `losses` 统一扣。

**目录风电的默认机型档（2026-09-15）**：公开电站没有机型字段，不再一律用通用曲线，
按投运年份与海上 / 陆上选档（`prediction_basis.catalog_turbine_class`），依据是 §8.1 的 REIT 场站电量对账：

| 场站 | 机型档 | 对账依据（实际 ÷ 模型） |
| --- | --- | --- |
| 陆上，`wind_catalog_modern_from_year`（2015）年起投运或年份未知 | `wind_catalog_modern_class`（`low_wind`） | 2016–2020 年投运的 5 座陆上站比功率 175–260 W/m²，通用曲线 126–203%；按比功率选档后 5 座为 87–109% |
| 陆上，更早投运 | 通用曲线 | 2011 年投运、370 W/m² 的恒润通用曲线 103%，中风速档 84% |
| 海上 | 通用曲线 | 滨海北通用 116%、中风速档 96%；庄河Ⅲ 通用 97%、中风速档 82%，换档没有一致改善 |

多期场址取按容量加权的中位投运年份。2012–2014 年投运的陆上站没有对账样本，按年份划入通用曲线档。
年份未知的场站多为新近并网，按新站处理。用户自建站点不受影响，未设置机型档仍为通用曲线。
海上风电另取海上格点，见 [04 §二](./04-data-specification.md)。

**为什么不用固定风切变指数外推**：风切变随大气稳定度昼夜变化，实测白天 α ≈ 0.11、
夜间 ≈ 0.29，差近 3 倍。固定 0.18 会把夜间大风算低、白天算高，日电量偏差 −15% 到 +16%，
而 Open-Meteo 本来就提供 80 / 100 / 120 / 200 m 各层风速。逐时按层插值把昼夜廓线差异带进来了。
地表粗糙度不单独获取：相邻两层风速已确定该时刻对数廓线的斜率与隐含 z0，模式本身也计入了下垫面与稳定度；
固定 z0 查表反而丢掉昼夜变化。微尺度地形加速需要高分辨率地形与实测标定，V1 不做。

**200 m 层（2026-09-14）**：ECMWF IFS 原生只有 10 / 100 / 200 m，80、120 m 由 Open-Meteo 推算（与 10、100 m
不满足精确的对数或幂律关系）。只请求到 120 m 时，140、160 m 轮毂只能沿 100–120 m 斜率外推。甘肃瓜州
（40.2°N, 97.0°E）三天样本中，夜间 100→200 m 风切变指数中位数为 −0.01；外推比使用 200 m 层间插值多算电量
140 m 轮毂 9.8%、160 m 轮毂 18.3%（ICON 为 8.0% / 14.7%，GFS 无 180、200 m）。单点预报因此加请求
`wind_speed_200m`，字段 14 → 15，计费权重 1.4 → 1.5；全目录统一 100 m 轮毂，不请求。样本仅一点三天，
只说明方向与量级。外推结果不单独标记估算，预测数据本身即为估算。

| 参数 | 默认值 |
| --- | --- |
| `v_in` 切入风速 | 3 m/s |
| `v_rated` 额定风速 | 12 m/s |
| `v_out` 切出风速 | 25 m/s |
| `losses` 场站损耗 | 0.10（尾流 + 可利用率 + 电气；光伏有 14% 系统损耗，风电此前为 0 是缺项） |
| `α` 风切变指数 | 0.18，只在缺高层数据时用（按 ERA5 10 m / 100 m 拟合，见 §八） |

风速取日间与夜间全部时段 —— 风电不分昼夜。


### 2.3 站点需要新增的字段

调研发现现有站点模型缺少物理建模必需的参数。
[04 §六](./04-data-specification.md) 与 [06 §5.2](./06-api-contract.md) 需相应补充。

| 字段 | 类型 | 必填 | 默认值 | 用途 |
| --- | --- | --- | --- | --- |

| `azimuth` | 光伏 | 否 | **180°（正南）** | 组件方位角，第 3 步 |
| `hub_height` | 风电 | 否 | **100 m** | 轮毂高度，各层风速插值的目标高度 |
| `turbine_class` | 风电 | 否 | `generic` | 机型档，§2.2 |
| `power_curve` | 风电 | `custom` 档必填 | — | 自定义功率曲线 `[{v, p}]`，§2.2 |
| `mounting` | 光伏 | 否 | `fixed` | 固定支架 / 单轴跟踪，§2.1 |
| `bifacial` | 光伏 | 否 | `false` | 双面组件，§2.1 |

默认值说明：

- 倾角取纬度是最大化年发电量的经验法则，对固定式光伏适用
- 方位角 180° 是北半球最优朝向
- 轮毂高度取单一默认值 100 m。早先按容量分档（`≤1.5MW → 70m` …）针对的是**单机**容量，
  而站点容量是全场容量，目录里所有场站都落在最高档，分档没有意义

三个字段都设为**选填**，不增加录入负担；
填了更准，不填用默认值，误差在可接受范围内。

> 若产品不希望增加字段，可全部用默认值，
> 但需在指数说明里标注「基于典型安装参数估算」。


### 2.4 等效利用小时

```
h_eq = E_day / C
```

单位统一后相除（kWh ÷ kW = h）。


### 2.5 如何验证算得对不对

没有实测数据时，用三条外部基准交叉验证：

| 方法 | 说明 |
| --- | --- |
| PVGIS | 欧盟联合研究中心的光伏产量估算服务，输入经纬度与容量，输出逐月发电量 |
| Global Solar Atlas | 世界银行项目，给出各地典型的 kWh/kWp 年产量 |
| 行业经验值 | 中国光伏年等效利用小时约 1000 – 1600 h（视地区），日均 2.7 – 4.4 h |

验证方式：

```
用模型跑目标站点整年的历史气象  →  年发电量
与上述基准对比，偏差应在 ±15% 以内
```

超出即说明参数（倾角、损失系数、温度模型）需要调整。

> 这一步与 1.8 的分布校准用同一批历史数据，一次跑完。

### 2.6 场站级出力约束（限电第一层）

限电是电网调度行为，和天气没有函数关系，模型推不出来。三条原则：

1. 环境指数只反映气象条件，**不受出力约束影响**。
2. 发电估算拆成两个口径：可发电量 `energy_kwh`（气象潜在值）与预计上网电量
   `grid_energy_kwh`（计入约束）。没有规则时后者一律 null，不用 0 或相等值冒充。
3. AI 报告拿两个数当输入，仍不做算术。

规则存在站点 `curtailment`，物理出力算完后按小时封顶（`services/curtailment.apply`）：

```
ratio     out_grid(h) = out(h) × (1 − ratio_percent / 100)
schedule  out_grid(h) = min(out(h), C × limit_percent / 100)   若 h 落在某时段内，多条取最小
```

时段按墙钟小时起点匹配。光伏 v4 逐时序列是区间末标签（13:00 表示 12:00–13:00），
匹配时减一小时；风电整点瞬时样本直接匹配。`end_hour` 不含，起点不小于终点表示跨零点；
`weekdays` 为 ISO 1–7，空表示每天。计划检修停机用同一机制，`limit_percent = 0`。
缺测保持 NaN，不因封顶变成 0。

逐日累积表 `daily_generation.kwh` 仍记可发电量，限电损失另记 `curtailed_kwh`。

第二层（省级月度利用率，2026-09-15）只作参考：公开电站与全目录汇总另给 `province_grid`
= 可发电量 × 所在省对应月份的风电 / 光伏利用率（当年当月没有时优先往年同月），不改可发电量、指数、累积与 AI 输入，
取值与范围见 [17 §四](./17-user-stations-and-outlook.md)。第三层（用负荷推限电）未做。

### 2.7 未来 7 天与时间粒度

`day_offset` 0…6 各跑一遍 §2.1 / §2.2 同一条链路（`services/prediction.compute_days`），
每天给日电量、指数分档与曲线；指数按 §一 对该日计算。7 天是四个模型的公共上限。
全目录汇总同样按天计算（15 分钟），顶层字段仍是今日，历史留档只封存当日，另按
「目标日 + 签发日」留一份供日后按预报时效评估。

**点预报统一粒度（2026-09-13）**：

| 天 | `lead_days` | 粒度 | 对应 |
| --- | --- | --- | --- |
| 当日 + 随后 3 天 | 0–3 | 15 分钟，96 点 | 短期（日前）：次日起 72 小时，15 分钟 |
| 第 5–7 天 | 4–6 | 15 分钟，96 点 | 时间间隔一致，不代表远期精度提高 |

15 分钟序列来自 Open-Meteo `minutely_15`，境内没有 15 分钟原生模式，是上游按晴空指数从
逐小时插值的，不含新的气象信息；意义在于格式对上报送要求，以及太阳位置按 15 分钟算让
日出日落前后的曲线形状更准。辐射同样是「前 15 分钟均值标在区间末」，太阳位置取区间中点
（提前 7.5 分钟），晴空基准取同一区间均值；光伏 v4 曲线的响应标签统一减一个步长改为区间起点。
线上只接受 15 分钟点预报，失败不另拉小时数据；archive 与旧留档保留真实的小时分辨率。超短期（未来 4 小时每 15 分钟滚动）需要
实测功率与卫星修正，尚未提供。


## 三、衍生指标


### 3.1 CO₂ 减排量

```
CO₂(吨) = E(kWh) × f / 1000

f = 0.8 kg CO₂/kWh      全国电网平均排放因子，可配置
```

排放因子应随电网结构变化定期更新，不要硬编码。


### 3.2 收益预估

```
R(元) = E(kWh) × p

p = 0.4 元/kWh          站点配置的上网电价，默认值
```

> 分时电价、市场化交易电价属于后续扩展，V1 用站点级固定电价。


### 3.3 环比

```
Δ% = (今值 − 昨值) / 昨值 × 100%
```

规则：

- 对比昨日**同期**（同一时刻或同一日累计口径），不是昨日全天
- 昨值缺失或为 0 时隐藏环比标签，不展示 0% 或 ∞
- 展示保留整数百分比
- 上升红色、下降绿色（表示变化方向，非好坏，见设计规范）

## 四、短临云层外推


### 4.1 云团移动

对相邻两帧卫星云图做位移估计，得到移动矢量 `(dx, dy)`。

```
v_cloud = √(dx² + dy²) / Δt        Δt = 10 分钟
θ = atan2(dx, dy)                  换算为 16 方位文案
```


### 4.2 影响时间

```
t_impact(分钟) = d / v_cloud × 60

d = 云团前沿到站点的距离（km）
v_cloud = 移动速度（km/h）
```

示例：80 km ÷ 107 km/h ≈ 45 分钟


约束：

- 外推时效上限 120 分钟，超出不出预警
- 云团移动方向偏离站点超过 ±45° 时不出预警


#### 实现口径（`app/satellite/motion.py`，已落地）

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 云像素 | 可见光反照率 > 100；红外亮温 > 48 | 可见光晴空 p99 = 44、云 p10 = 104；红外看不到低暖云，48 命中约六成可见光云、误判 1% |
| 位移估计 | Farneback 稠密光流，按 Sobel 梯度幅值加权平均 | 均匀云内部光流为 0，中位数会严重低估 |
| 静止阈值 | < 5 km/h 不外推 | 噪声级位移 |
| 来向锥 | 以站点为顶点、指向云团来处、半角 45°，搜索半径 400 km | 即「偏离 ±45° 不出预警」 |
| 距离 | 锥内最近云像素到站点的距离 | 云前沿 |
| 站点已在云下 | `distance = 0`，`impact = 0`，预警文案改为「正在过境」 | |
| 预警等级 | ≤30 分钟 severe，≤60 moderate，其余 minor | |
| 无云 | 云像素少于画面 0.5% → 不估计 | |
| 帧间隔 | 按两帧实际时刻算，> 25 分钟不外推 | JMA 偶有缺帧 |

合成云团测试：8 px 对角位移（≈68 km/h）估出 60–64 km/h，方向误差 < 5°。
真实精度需真机/历史回放校准，V1 先按此口径出预警。
夜间用红外，低暖云漏检使外推偏保守（漏报多于误报）。


### 4.3 辐射降幅

```
drop% = (GHI_clear − GHI_forecast) / GHI_clear × 100%

GHI_clear = 晴空理论辐射
```

```
GHI_clear = 1361 × sin(h_sun) × τ

h_sun = 该时刻的太阳高度角
```

太阳高度角与 τ 见 [附录 A](#附录-a太阳位置计算)，与环境指数共用同一份实现。
实现上 `GHI_clear` 取与预报同口径的**小时均值**（pvlib Ineichen），
只在晴空小时均值 ≥ 100 W/m² 的时段比较 —— 日出日落边缘的 kt 噪声大，且对发电无关紧要。

## 五、预警触发规则


### 5.1 云层 / 辐射风险

| 预计辐射降幅 | 等级 |
| --- | --- |
| < 20% | 轻度 |
| 20% – 40% | 中度 |
| > 40% | 重度 |

低于 10% 不触发预警。


### 5.2 天气异常

| 类型 | 触发条件 | 等级 |
| --- | --- | --- |
| 强风 | 风速 > 15 m/s | 中度 |
| 强风 | 风速 > 25 m/s（风机切出） | 重度 |

风速取值高度：**风电站按轮毂高度**（与 §2.2 功率曲线同口径），光伏站按 10 m。
切出判断只有在轮毂高度上才对得上：10 m 风速 16.5 m/s 时 100 m 处已约 25 m/s，
功率曲线已归零，按 10 m 判要等到 25 m/s 才报，用户会看到功率骤降却没有预警。
| 暴雨 | `weather_code` 命中暴雨类 | 中度 |
| 高温 | 气温 > 38℃ | 中度 |
| 低温 | 气温 < −10℃ | 中度 |

高温 / 低温取**严格**不等号，恰好等于阈值不触发。


### 5.3 解除预警

原预警条件不再满足，且持续 30 分钟稳定，生成一条「解除预警」记录。

实现：`last_detected_at` 仅记录最近命中时间。首次有效扫描未命中时记录
`clear_since`，此后有效扫描持续未命中满 30 分钟才解除；正常每 15 分钟扫描，
至少需要首次确认消失、15 分钟、30 分钟三个观测点。再次命中则清空解除计时。
`last_clear_check_at` 记录最近一次确认消失的时间；确认间隔超过 20 分钟
（15 分钟调度间隔加 5 分钟余量）后重新计时，避免把扫描中断算作稳定期。
卫星结论未知时清空解除计时并保留预警，既有卫星预警自然过期规则不变。
不这样做，临界条件会产生「预警 / 解除 / 预警」抖动。


### 5.4 去重

同一站点同一类型的预警，2 小时内不重复推送，仅更新已有记录。

## 八、上线前必做的校准


指数与发电估算都依赖参数，参数没校准过就上线，数字不可信。

以下三步用同一批历史数据一次跑完：

| # | 步骤 | 方法 | 判据 |
| --- | --- | --- | --- |
| 1 | 发电量准确度 | 与 PVGIS / Global Solar Atlas 对比年发电量 | 偏差 ≤ ±15% |
| 2 | 指数分布 | 5 个气候区 × 365 天，看分数分布 | 不过度集中于单一档位 |
| 3 | 分档直觉 | 抽查典型晴天 / 阴天 / 雨天 | 档位与人工判断吻合 |

数据来源：Open-Meteo archive API，拉过去 365 天历史气象。

> 调整顺序：先调模型参数（第 1 步），再调分档阈值（第 2、3 步）。
> **不要为了让分布好看去改指数定义** —— 定义有物理意义，阈值只是展示分档。

## 附录 A·太阳位置计算


用于确定日间时段与晴空辐射基准。


> **实现用 `pvlib`，不要手写本附录的公式。**
>
> 本附录给出的是**口径定义**——说明这些量是什么、怎么用，便于评审与对账。
> 实际实现直接调 `pvlib`（NREL 支持的光伏建模标准库），精度远高于下面的简化式：
>
> | 本附录 | pvlib |
> | --- | --- |
> | A.1 太阳赤纬 / A.2 时角日长 | `solarposition.get_solarposition()`（SPA 算法） |
> | A.2 日出日落 | `solarposition.sun_rise_set_transit_spa()` |
> | A.3 均时差与经度修正 | 已包含在上述函数中，无需单独实现 |
> | A.4 晴空日累计辐射 | `clearsky.ineichen()` 或 `simplified_solis()` |
>
> 简化公式只在需要脱离 pvlib 的场景（如端上估算）作为降级实现。


### A.1 太阳赤纬

```
n = 日序数（1 – 365/366）

δ = 23.45° × sin(360° × (284 + n) / 365)
```


### A.2 日长与日出日落

```
φ = 站点纬度

时角  ω_s = arccos(−tan φ × tan δ)

日长 = 2 × ω_s / 15          小时

日出（太阳时） = 12 − ω_s / 15
日落（太阳时） = 12 + ω_s / 15
```


极昼极夜处理：

```
−tan φ × tan δ > 1    →  极夜，日长 = 0
−tan φ × tan δ < −1   →  极昼，日长 = 24
```

境内站点不会触发，但海外扩展时必须处理，否则 `arccos` 定义域越界。

**实现注意**：`pvlib.solarposition.sun_rise_set_transit_spa` 按 **UTC 日期**取日序。
东八区的当地 00:00 还落在前一个 UTC 日，直接传当地零点会整体算成前一天的日出日落
（问北京 9 月 9 日会返回 9 月 8 日的 05:49–18:35）。传**当地正午**即可。
实现见 `metrics/solar.daylight_window`。


### A.3 转换为本地钟表时间

```
钟表时 = 太阳时 − (经度 − 时区中央经线) × 4分钟 − EoT

EoT = 均时差（分钟）
B = 360° × (n − 81) / 364
EoT = 9.87 sin(2B) − 7.53 cos(B) − 1.5 sin(B)
```

中国全境用 UTC+8，中央经线 120°E。


### A.4 晴空日累计辐射

```
峰值太阳高度角  h_max = 90° − |φ − δ|

峰值晴空辐射   G_peak = 1361 × sin(h_max) × τ

晴空日累计     E_clear = G_peak × 日长 × 2/π
```

| 参数 | 含义 | 默认值 |
| --- | --- | --- |
| `1361` | 太阳常数（W/m²） | 固定 |
| `τ` | 大气透射率 | 0.75 |
| `2/π` | 正弦半波日积分系数 | 0.6366 |


### A.5 精度

| 实现 | 日出日落误差 | 晴空辐射误差 |
| --- | --- | --- |
| 本附录简化公式 | ±2 分钟 | ±5% |
| `pvlib`（SPA + Ineichen） | ±1 秒量级 | 显著优于简化式 |

用 pvlib 时精度不是需要担心的项。
简化公式的误差记录在此，仅供理解量级与降级实现参考。


### A.6 使用位置
