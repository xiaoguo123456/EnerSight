## 二、气象数据


### Open-Meteo


用途：

提供全球天气实况与预测。


接口：

```
https://api.open-meteo.com/v1/forecast
```


请求方式：

按站点经纬度逐点请求，结果按站点缓存。

### 实时天气


对应界面：首页「实时环境数据」四宫格、地图页底部站点卡、站点详情「当前天气」。


| 展示项 | 字段 | 单位 | 说明 |
| --- | --- | --- | --- |
| 气温 | `temperature_2m` | ℃ | 2 米气温 |
| 体感温度 | `apparent_temperature` | ℃ | 地图页「体感 34℃」 |
| 湿度 | `relative_humidity_2m` | % | |
| 风速 | `wind_speed_10m` | m/s | 10 米风速，界面展示值 |
| 高层风速 | `wind_speed_80m` / `_100m` / `_120m` | m/s | 风电轮毂高度风速按各层对数廓线插值（07 §2.2），不展示 |
| 风向 | `wind_direction_10m` | ° | 0–360，正北为 0，顺时针 |
| 云量 | `cloud_cover` | % | 总云量 |
| 分层云量 | `cloud_cover_low` / `_mid` / `_high` | % | 用于云层风险判断 |
| 天气现象 | `weather_code` | WMO code | 映射为「晴」「晴转多云」等文案 |
| 数据时间 | `time` | ISO8601 | 界面显示为「数据更新时间」 |


---

### 昨日同期对比数据


界面上「较昨日 ↑12%」「较昨日 ↓8%」的环比标签依赖此数据，
不能由实时天气单独计算得出。


获取方式：

```
forecast 接口追加 past_days=1
```


对比口径：

```
今日 T 时刻值  vs  昨日 T 时刻值

差值百分比 = (今值 - 昨值) / 昨值 × 100%
```


参与环比的指标：

- 气温
- 风速
- 云量
- 辐射
- 站点发电量（来自站点数据，非气象）


展示规则：

| 情况 | 展示 |
| --- | --- |
| 上升 | ↑ 红色 |
| 下降 | ↓ 绿色 |
| 昨值缺失或为 0 | 隐藏环比标签 |

> 说明：升为红、降为绿是设计稿中的既定用法（强调"变化幅度"而非"好坏"），实现时不要按涨跌习惯反转配色。

包括：

- 未来小时天气（`hourly`，24 小时趋势图）
- 未来 7 天天气（`daily`）

| 趋势 Tab | 字段 | 单位 | 纵轴范围 |
| --- | --- | --- | --- |

### 太阳相关数据


包括：

| 名称 | 字段 | 单位 | 用途 |
| --- | --- | --- | --- |
| Shortwave Radiation | `shortwave_radiation` | W/m² | 总辐射，界面主展示值 |
| Direct Radiation | `direct_radiation` | W/m² | 直射分量 |
| Diffuse Radiation | `diffuse_radiation` | W/m² | 散射分量 |
| DNI | `direct_normal_irradiance` | W/m² | 法向直射 |
| GTI | `global_tilted_irradiance` | W/m² | 倾斜面总辐射，光伏发电估算用 |

**时间口径**：Open-Meteo 的小时辐射是**前一小时的平均值**，标在区间末 ——
标注 13:00 的值对应 12:00–13:00。与之配合的太阳位置要取区间中点 12:30，
晴空基准也取同一区间的均值（07 §2.1）。瞬时值另有 `*_instant` 字段，本项目不用。


### 区间均值量与瞬时量

**同一份 hourly 里两种时间语义并存，取「当前」时不是同一格。**

| 语义 | 字段 | 标签含义 | 「当前」取哪一格 |
| --- | --- | --- | --- |
| 区间均值 | `shortwave_radiation`、`direct_radiation`、`diffuse_radiation`、`direct_normal_irradiance` | 前一小时均值，标在区间末 | 包含当前时刻的区间，即 `ceil` |
| 瞬时 | `temperature_2m`、`apparent_temperature`、`relative_humidity_2m`、各层 `wind_speed_*`、`wind_direction_10m`、`cloud_cover*`、`weather_code` | 标注时刻的瞬时值 | 当前整点，即 `floor` |

由辐射推出的量（光伏逐时出力、晴空指数 kt）跟随辐射走；
由瞬时风速推出的量（风电逐时出力、强风预警）跟随瞬时值走。

实现见 `services/weather.Forecast.current_hour()` 与 `current_interval()`：

```
06:30  →  current_hour() = 06:00     气温 / 风速 / 云量
          current_interval() = 07:00  辐射 / 光伏出力 / kt
```

整点时两者相同，取到的是刚结束的完整区间。
统一用 `floor` 会拿已经过去的那一小时当「当前」：北京夏至日 06:30 的光伏出力
会报成 19 kW 而不是 84 kW，日落后一小时则反向高估。


用途：

分析太阳能资源、估算光伏发电量。

## 三、卫星遥感数据


### Himawari（葵花卫星）


主要用途：

实时云图。


基础参数：

| 项 | 值 |
| --- | --- |
| 卫星 | Himawari-9（AHI 传感器） |
| 覆盖 | 东亚 – 西太平洋全圆盘 |
| 更新频率 | 10 分钟 |
| 时间戳展示 | 预警页卫星云图左上角「2024-07-20 14:00」 |


使用：

#### 可见光

波段：

B03（0.64 μm），空间分辨率 0.5 km。


用途：

- 白天云层观察
- 云覆盖范围


限制：

夜间无可见光信号，需自动切换至红外。

> **V1 实际落地（2026-09）：** 数据源用日本气象厅（JMA）官网的 Himawari-9 瓦片
> `www.jma.go.jp/bosai/himawari/data/satimg/{time}/fd/{time}/{band}/{z}/{x}/{y}.jpg`，
> Web Mercator XYZ，最高 z=5（约 4–5 km/px），10 分钟一帧，`targetTimes_fd.json` 给可用时刻。
> 四个产品都有：`B03/ALBD` 可见光反照率、`B13/TBB` 红外亮温、`B08/TBB` 水汽、`REP/ETC` 真彩。
> **昼夜按站点太阳高度角（> 5°）切换**：白天分析用 B03、展示用真彩；夜间分析与展示都用 B13。
> 云量强度是渲染灰度的代理，不是定量云量：可见光阈 100（晴空 p99 = 44），
> 红外阈 48（红外看不到低暖云，同图只命中约六成可见光云、误判 1%，夜间偏保守）。
> 曾用 NICT 真彩图（无红外），已弃用。JMA 瓦片是网页自用接口无 SLA，
> 正规兜底是 NOAA 开放数据 `s3://noaa-himawari9`（L1b 全波段，需自行解码投影），见 09。


#### 红外

波段：

B13（10.4 μm），空间分辨率 2 km。


用途：

- 全天云层检测
- 云顶温度分析


#### 水汽

波段：

B08（6.2 μm），空间分辨率 2 km。


用途：

- 大气湿度
- 天气变化趋势


---

### 卫星数据应用


用于：

#### 云层识别


判断：

当前位置是否有云。


输出：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `cloud_over_site` | bool | 站点上空是否被云覆盖 |
| `cloud_intensity` | 0–1 | 云量强度，对应预警页「云量强度」低—高图例 |


#### 云团移动


分析：

- 移动方向
- 移动速度


方法：

对相邻两帧云图做位移估计，得到云团移动矢量。

**已落地：** 站点周边 ±2.5° 重投影成 512px 等经纬度图，
相邻两帧做 Farneback 稠密光流，按梯度幅值加权取平均位移
（大片均匀云内部光流为 0，直接取中位数会严重低估）。帧间隔按实际时刻算（JMA 偶有缺帧），
超过 25 分钟不做外推。夜间用红外，也能出短临预警。实现与阈值见 [07 §四](./07-metrics.md)。


#### 短临预警


预测：

未来几十分钟云层影响。


外推输出字段（对应预警页三宫格）：

| 展示项 | 字段 | 单位 | 示例 |
| --- | --- | --- | --- |
| 云团距离 | `cloud_distance_km` | km | 80 |
| 移动方向 | `cloud_direction` | 方位文案 | 东北 |
| 移动速度 | `cloud_speed_kmh` | km/h | 内部计算，不直接展示 |
| 预计影响时间 | `impact_in_minutes` | 分钟 | 45 |
| 影响起始时刻 | `impact_start_time` | HH:mm | 14:30 |
| 预计辐射降幅 | `radiation_drop_percent` | % | 20 |

计算：

```
预计影响时间 = 云团距离 ÷ 移动速度
```

外推时效上限：120 分钟，超出不出预警。

## 四、地图图层数据规格


地图页固定 5 个图层，同一时刻仅一个数据图层激活（站点图层可与其叠加）。


### 图层总览

| 图层 | 数据源 | 数据形态 | 单位 | 更新频率 |
| --- | --- | --- | --- | --- |
| 云图 | Himawari | 卫星影像瓦片 | — | 10 分钟 |
| 风场 | Open-Meteo 网格 | 矢量场（U/V） | m/s | 1 小时 |
| 温度 | Open-Meteo 网格 | 标量场 | ℃ | 1 小时 |
| 辐射 | Open-Meteo 网格 | 标量场 | W/m² | 1 小时 |
| 站点 | 用户站点数据 | 点要素 | — | 实时 |


---

### 云图图层


数据：

Himawari 可见光 / 红外 / 水汽三选一，默认按当地昼夜自动切换可见光与红外。

**已落地：** 白天用可见光反照率、夜间用红外亮温，重投影为等经纬度后按波段区间
线性拉伸为强度，透明度随强度变化；卫星源不可用时退回 Open-Meteo 预报 `cloud_cover`。
两种来源共用同一套图例，`observed_at` 分别为卫星观测时刻 / 预报小时。


渲染：

栅格瓦片叠加在底图之上。


图例：

```
云量强度   低 ——————— 高
```

叠加透明度：0.75，避免完全遮挡行政边界与地名。


---

### 风场图层


数据：

网格化风速与风向。


> 注意：流线动画需要正交分量 U / V，Open-Meteo 返回的是「风速 + 风向」标量对，
> 必须在渲染前换算，否则无法绘制设计稿中的白色流线。

换算：

```
u = -wind_speed × sin(wind_direction × π / 180)

v = -wind_speed × cos(wind_direction × π / 180)
```


渲染：

- 底色：风速色阶
- 叠加：白色流线粒子动画，流线方向即风向，粒子速度正比于风速


网格：

请求分辨率 0.25°，按当前视窗范围裁剪。


---

### 温度图层


数据：

网格化 2 米气温。


渲染：

连续色阶填充。


图例：

```
温度（℃）

-20  -10   0   10   20   30   40
```


---

### 辐射图层


数据：

网格化短波辐射。


渲染：

连续色阶填充。


图例（对应地图页左下角）：

```
辐射强度（W/m²）

0   200   400   600   800   1000
```

色阶方向：

```
低 蓝 → 青 → 绿 → 黄 → 橙 → 红 高
```

超过 1000 W/m² 的值按 1000 截断显示。


---

### 站点图层


数据：

用户自建站点。


渲染：

| 元素 | 说明 |
| --- | --- |
| Marker | 按站点类型区分图标（光伏 / 风电） |
| 状态色 | 运行正常绿色，设备待机蓝色，异常红色 |
| 当前站点 | 蓝色定位点 + 名称气泡（如「苏州」） |
| 聚合 | 同屏站点超过 20 个时按距离聚合为数字簇 |


---

### 图层通用规则


| 项 | 规则 |
| --- | --- |
| 图例 | 每个数据图层拥有独立图例，切换图层时同步切换 |
| 时间戳 | 图层左上角显示数据观测时间，非当前系统时间 |
| 比例尺 | 右下角显示，随缩放级别变化（如 200 km） |
| 缩放级别 | 3 – 12；低于 5 时不加载站点图层 |
| 数据缺失 | 图层保持底图可见，顶部提示「该区域暂无数据」 |
| 请求范围 | 仅请求当前视窗 bbox，拖动结束 300ms 后再发起请求 |

> 设计稿待确认：`地图.png` 中图层切换器高亮的是「云图」，而左下角图例为「辐射强度（W/m²）」，
> 两者不对应。该图应为综合效果示意，实现时图例必须绑定当前激活图层。


### 运行状态

| --- | --- | --- |
| 运行正常 | 绿色 | 正常发电 / 待命 |

### 光伏 / 风电 运行指标


对应站点列表卡片四宫格。

| 展示项 | 字段 | 单位 | 示例 |
| --- | --- | --- | --- |
| 今日发电 | `daily_generation` | kWh | 2,400 |
| 实时功率 | `current_power` | kW / MW | 320 kW |
| 累计发电 | `total_generation` | GWh | 1.26 |
| 减排量 | `co2_reduction` | 吨 | 1,008 |


估算口径（V1 无实测数据时）：

```
光伏 ≈ GTI × 装机容量 × 系统效率 × 时长

风电 ≈ 风速 → 功率曲线 → 出力 × 时长

CO₂ 减排 = 累计发电量 × 排放因子
```

排放因子：0.8 kg CO₂/kWh（全国电网平均，可配置）。

## 七、公开电站目录


用户自己录站点的可能性不大，目录让产品「一打开就有内容」：地图上能看到周边真实场站，
添加站点时可以直接选一座。


### 数据来源

| 来源 | 内容 | 授权 | 获取 | 状态 |
| --- | --- | --- | --- | --- |
| WRI Global Power Plant Database v1.3 | 全球 3.5 万座电站，中国光伏 1,318 座、风电 835 座，英文名、坐标、容量、投运年份、业主，数据截至 2021 | CC BY 4.0 | GitHub 直接下载 CSV | **已导入** |
| Global Energy Monitor：Global Solar / Wind Power Tracker（2026-02 版） | ≥ 1 MW 场站，中国 operating 光伏 13,618 期 / 风电 5,997 期，合并同址后 12,875 / 4,860 座，**带中文名**、省市县、业主、多期容量，每季度更新 | CC BY 4.0（TransitionZero 的 CC BY-NC 部分只在「Distributed (<1 MW)」表，不导入） | 官网表单：提交联系人信息换令牌，再换预签名地址；`app/catalog/gem.py` 已自动化 | **已导入**，定时任务按月同步 |

目录合计 18,764 座（GEM 17,735 + WRI 未被覆盖的 1,029），17,506 座有中文名。

不用的：JAXA P-Tree（禁止再分发）、OpenStreetMap（ODbL 传染性，衍生库需同许可开放）、
北极星等商业库。


### 导入与合并

```
uv run python scripts/import_catalog.py wri global_power_plant_database.csv
uv run python scripts/import_catalog.py gem Global-Solar-Power-Tracker.xlsx
uv run python scripts/import_catalog.py gem Global-Wind-Power-Tracker.xlsx
```

- 只导 `operating` 且 ≥ 1 MW 的光伏、风电；容量统一存 kW
- 同类型、相距 < 1.5 km 视为同一座：GEM 优先，覆盖 WRI；GEM 同一场址多期合并
- 幂等：按 `{source}:{source_id}` 更新
- 省市区：GEM 的省份映射成中文，市县暂为英文；配了腾讯 key 后回填任务逐步换成中文
- **定期同步**：`sync_catalog` 每天凌晨检查，距上次成功超过 `catalog_sync_days`（默认 30）
  就用 `ENERSIGHT_GEM_CONTACT_*` 里的联系人提交 GEM 表单、下载两份 xlsx 重新导入；
  这次没出现的 GEM 条目标记 `retired`，搜索与 marker 不再显示，用户已添加的站点不动。
  每次同步都会在 GEM 那边留一条提交记录，不要把周期调得比月更短


### 展示要求

- 列表与地图 marker 处注明出处「WRI Global Power Plant Database（CC BY 4.0）」，
  有 GEM 数据时加 「Global Energy Monitor」—— CC BY 的署名条款，不能省
- 目录只读、全体共享；用户添加时复制一份到自己的站点并记 `catalog_id`
- 容量是数据集口径（多为交流侧 MW），与用户自填的装机容量语义一致

### 时段分析


AI 报告将一天切分为三段输出。

| 时段 | 时间区间 | 输出内容 |
| --- | --- | --- |
| 上午 | 06:00 – 12:00 | 天气概况 + 发电条件结论 |
| 下午 | 12:00 – 18:00 | 天气概况 + 发电条件结论 |
| 晚间 | 18:00 – 24:00 | 天气概况 + 对次日影响 |

每段字段：`weather_summary`、`generation_impact`、`level`（用于时间轴节点配色）。

### 数据摘要


| 展示项 | 字段 | 单位 | 示例 |
| --- | --- | --- | --- |
| 发电量 | `generation` | kWh | 6,320 |
| 等效利用小时 | `equivalent_hours` | h | 4.5 |
| CO₂ 减排 | `co2_reduction` | 吨 | 4.8 |
| 收益预估 | `estimated_revenue` | 元 | 2,528 |

计算：

```
等效利用小时 = 发电量 ÷ 装机容量

收益预估 = 发电量 × 上网电价
```

> 电价依赖：收益预估需要电价参数。V1 使用站点配置的固定上网电价（默认 0.4 元/kWh），
> 分时电价与市场化电价属于后续扩展。

四项均带昨日环比。

### model-v4 日边界补充

光伏输入仍是区间末标注，但日预测响应统一改为区间起点标注；例如 12:00–13:00
使用辐射标签 13:00，预测曲线显示 12:00。瞬时风速与风电曲线仍使用整点起点。
原始气象趋势保留上游标签，不能据相同标签直接与混合功率相加。

### 2026-09 IFS HRES 地图网格升级

温度、风场、辐射固定使用 Open-Meteo AWS `data_spatial/ecmwf_ifs` 的 IFS HRES O1280
原生约 9 km 网格，不调用经纬度点查询拼接地图。温度取 `temperature_2m`，风直接取
`wind_u_component_10m` / `wind_v_component_10m`，辐射取 `shortwave_radiation`（W/m²）。
按完整起报批次选择当前预报时刻：温度、风向下取整点，辐射向上取区间末标签。
地图重采样只是展示投影，不声明比源网格更高的分辨率；缺测保持透明，不填零。
首页可选模型暂不影响地图固定 HRES 数据源。来源署名 ECMWF / Open-Meteo，CC BY 4.0。
