## 二、气象数据


### Open-Meteo


用途：

提供全球天气实况与预测。


接口：

```
https://api.open-meteo.com/v1/forecast
```


请求方式：

按站点经纬度逐点请求，结果按站点缓存。

### 实时天气


对应界面：首页「实时环境数据」四宫格、地图页底部站点卡、站点详情「当前天气」。


| 展示项 | 字段 | 单位 | 说明 |
| --- | --- | --- | --- |
| 气温 | `temperature_2m` | ℃ | 2 米气温 |
| 体感温度 | `apparent_temperature` | ℃ | 地图页「体感 34℃」 |
| 湿度 | `relative_humidity_2m` | % | |
| 风速 | `wind_speed_10m` | m/s | 10 米风速，界面展示值 |
| 高层风速 | `wind_speed_80m` / `_100m` / `_120m` / `_200m` | m/s | 风电轮毂高度风速按各层对数廓线插值（07 §2.2），不展示；200 m 仅单点预报请求 |
| 风向 | `wind_direction_10m` | ° | 0–360，正北为 0，顺时针 |
| 云量 | `cloud_cover` | % | 总云量，云层预警阈值也用它 |
| 天气现象 | `weather_code` | WMO code | 映射为「晴」「晴转多云」等文案 |
| 数据时间 | `time` | ISO8601 | 界面显示为「数据更新时间」 |

### 昨日同期对比数据


界面上「较昨日 ↑12%」「较昨日 ↓8%」的环比标签依赖此数据，
不能由实时天气单独计算得出。


获取方式：

```
forecast 接口追加 past_days=1
```


对比口径：

```
今日 T 时刻值  vs  昨日 T 时刻值

差值百分比 = (今值 - 昨值) / 昨值 × 100%
```


参与环比的指标：

- 气温
- 风速
- 云量
- 辐射
- 站点发电量（来自站点数据，非气象）


展示规则：

| 情况 | 展示 |
| --- | --- |
| 上升 | ↑ 红色 |
| 下降 | ↓ 绿色 |
| 昨值缺失或为 0 | 隐藏环比标签 |

> 说明：升为红、降为绿是设计稿中的既定用法（强调"变化幅度"而非"好坏"），实现时不要按涨跌习惯反转配色。

### 未来预测


包括：

- 点预报统一请求 `minutely_15`，不再另发 `hourly` 请求。首页、预警、报告、单站预测共享一份缓存。
- 单站请求 `forecast_days=8`、`past_days=1`：昨日同期、今日起七天及第七天末区间边界，共最多 864 点。
  四模型采用七天公共预测范围；超出模式预报范围的额外点可能为空，不能用零补齐。
- 请求 15 个实际使用字段：气温、体感、湿度、10/80/100/120/200 m 风速（200 m 供轮毂高于 120 m 的风电站层间插值，
  GFS 无此层；全目录统一 100 m 轮毂不请求）、10 m 风向、云量、天气代码、
  辐射三项及地面气压。中国区域由上游插值，15 分钟不是原始气象精度的提升。
- 单站、全目录的七天功率均为每日 96 点；24 小时气象趋势含次日零点，共 97 点，七天趋势 672 点。
- 线上缺少 15 分钟响应时返回上游不可用，不另请求小时数据。历史小时资料解析保留原始 60 分钟步长。
- 全目录天气按网格内容指纹落盘，仅保留最近 8 格在内存中，清单标明 15 分钟；输入留档逐块写入并计算指纹。
- `surface_pressure`（hPa）与响应里的 `elevation`（90 m DEM）：风电空气密度修正用，
  见 [07 §2.2](./07-metrics.md)。


### 全目录汇总的网格步长

汇总按网格取气象，**光伏 1°、风电 0.25°**（`fleet_grid_step_solar` / `_wind`）。

2026-09-13 抽样 98 座按容量加权的场站，以**场站真实坐标**为基准对比当日电量：

| | 逐站 \|误差\| 中位 | P90 | 容量加权汇总偏差 |
| --- | --- | --- | --- |
| 光伏 1° | 2.7% | 19.1% | **+0.75%** |
| 光伏 0.25° | 0.8% | 3.4% | +0.15% |
| 风电 1° | 31.0% | 238.9% | **−8.46%** |
| 风电 0.25° | 14.1% | 59.5% | +0.09% |

辐射场在百公里尺度上平滑，光伏在 1° 上汇总偏差已不到 1%；风速对地形极敏感，
1° 下风电偏差 −8.46%，细化到 0.25° 才降到噪声水平。

**逐站误差远大于汇总误差是正常的** —— 汇总是容量加权求和，高估与低估互相抵消。
所以这个粒度只对「全目录合计」这个用途成立；单站预测一律走站点真实坐标，不用网格。

**海上风电取海上格点（2026-09-15）**：Open-Meteo 默认 `cell_selection=land`，近岸坐标优先落到
陆地格点。REIT 场站对账里滨海北 H1 被分到陆地，10 m 风 3.66 m/s（海上格点 5.25 m/s），电量少算三成
（[07 §8.1](./07-metrics.md)）。目录海上风电（GEM `Installation Type` 为 Offshore；导入该字段前的旧库
按名称含 Offshore / 海上识别，2026-02 版两者 156 期完全一致）的单点预报与全目录网格都带
`cell_selection=sea`：单点缓存键加 `:sea`；全目录分组键带格点选择，与同格心的陆上场站分开，
海上格点单独成一次请求，陆上格的键不变。

坐标预算（去重后，每天两轮）：

| 配置 | 坐标 | 每天 | 免费层 10,000 |
| --- | --- | --- | --- |
| 全 1° | 655 | 1,310 | 13% |
| **1° / 0.25°（当前）** | **2,747** | **5,494** | **55%** |
| 全 0.25° | 3,332 | 6,664 | 67% |

风电占可算场站的六成（4,860 / 8,225），所以分类型只比全 0.25° 省 18%。
把光伏也调到 0.25° 每天多 1,170 个坐标，换来光伏汇总偏差 +0.75% → +0.15%，
改一个配置值即可。

> 单日样本，风电误差随天气型态波动很大。要下最终结论应在历史数据上跑多日。


### 字段预算与拉取节奏

Open-Meteo 按**加权调用数**计费，不是按请求数：超过 10 个变量或超过 2 周跨度的请求
按比例计为多次调用（15 个变量的 2 周请求 = 1.5 次）。免费层 10,000 次/天且**禁止商用**，
商用最低档 $29/月 1M 次。

因此两条硬规矩：

**① 字段只列有消费方的。** 清单在 `providers/open_meteo.HOURLY_FIELDS`，新增前先确认谁读它，
并同步本节的表。曾经带过 `direct_radiation`、`is_day`、`cloud_cover_low/_mid/_high` 五个字段，
全项目无人读取，白付了 26% 的权重。出力模型必需的 9 个字段有回归测试兜底，删不掉。

**② 按回源时段与模型批次限次，不按短 TTL。** 上游每 6 小时出一批（00/06/12/18 UTC，落地比起报晚
3–6 小时），而定时任务每 15 分钟扫一轮。若按 10 分钟 TTL 缓存，每个网格每天回源 96 次，
其中 92 次拿回来的字节完全相同。拉取节奏因此按两条链路分别封顶：

| 链路 | 每天上限 | 规则 | 实现 |
| --- | --- | --- | --- |
| 实测订正回算（`providers/open_meteo.recent_hourly`，[19 §三](./19-forecast-uncertainty-and-observations.md)） | 每电站每档每天 1 次 | 逐小时、`past_days` 按 7 / 31 / 92 分档、`forecast_days=1`，字段同主请求不新增权重；只在记录实测与每日拟合时发生，自建实例下不计费 | `services/hindcast.weather` |
| 单点预报（自建场站、公开电站详情、首页、预警、报告共用） | 每坐标每模型 4 次 | 缓存键 `15m:{model}:{精确经纬度}`（海上风电另加 `:sea`，见上节）；当地一天按 `forecast_refreshes_per_day` 等分为 4 个时段。同一时段内命中、不追新批次；进入新时段但起报批次没变仍命中；跨当地日必定刷新（第七天末边界与昨日同期依赖当天请求）。元数据拿不到时每个时段回源一次 | `services/weather.get_forecast` |
| 全目录预测 | 每模型整轮 1 次 | 北京时间 `fleet_refresh_hour`（08:00，Open-Meteo 日额度按 UTC 零点重置）起拉当天一轮，此前沿用上一日快照里对应日期的预测。同一天内新批次、元数据缺失、快照重算都复用当天已取得的坐标，起报以当天首轮为准；部分覆盖每半小时续算，只补拉缺失坐标，续拉轮数上限 `fleet_fetch_rounds_per_day`（4） | `services/fleet_prediction.ensure` / `build` |

代价是新鲜度：单点最多晚一个时段（6 小时）才看到新批次，全目录当天不追新批次。
批次标识见 `services/weather.batch_stamp`；元数据缺失时为 `unknown-{时间片}`，不能用固定字符串。

### 起报时间

Open-Meteo 点预报响应不带模型起报时刻，要另调各模型元数据：

```
https://api.open-meteo.com/data/{slug}/static/meta.json
  last_run_initialisation_time   起报（Unix 秒，UTC）
  last_run_availability_time     该批数据可用时刻
  update_interval_seconds        更新间隔
```

| 请求模型 | 元数据 slug | 说明 |
| --- | --- | --- |
| `best_match` | `ecmwf_ifs` | 境内实测等于 ECMWF IFS 9 km，服务端每日三点复核，不一致时退回不显示起报 |
| `ecmwf_ifs` | `ecmwf_ifs` | |
| `gfs_global` | `ncep_gfs013` | 由 0.13° 与 0.25° 两套拼成，起报不同，以 0.13° 为准 |
| `icon_global` | `dwd_icon` | |

响应里以 `ForecastBasis` 给出：`model`、`resolved_model`、`issued_at`、`available_at`、`fetched_at`。
`issued_at` 为 null 表示无法确认起报，前端只显示拉取时间，不猜。元数据显示 9 km 数据只覆盖到
起报后约 6 天，第 7 天由上游用更早或更粗的批次补齐，起报标注「以首日为准」。见 [17 §二](./17-user-stations-and-outlook.md)。

### 太阳相关数据


包括：

| 名称 | 字段 | 单位 | 用途 |
| --- | --- | --- | --- |
| Shortwave Radiation | `shortwave_radiation` | W/m² | 总辐射，界面主展示值 |
| Diffuse Radiation | `diffuse_radiation` | W/m² | 散射分量 |
| DNI | `direct_normal_irradiance` | W/m² | 法向直射 |
| GTI | `global_tilted_irradiance` | W/m² | 倾斜面总辐射，光伏发电估算用 |

**时间口径**：Open-Meteo 的小时辐射是**前一小时的平均值**，标在区间末 ——
标注 13:00 的值对应 12:00–13:00。与之配合的太阳位置要取区间中点 12:30，
晴空基准也取同一区间的均值（07 §2.1）。瞬时值另有 `*_instant` 字段，本项目不用。


### 区间均值量与瞬时量

**同一份 hourly 里两种时间语义并存，取「当前」时不是同一格。**

| 语义 | 字段 | 标签含义 | 「当前」取哪一格 |
| --- | --- | --- | --- |
| 区间均值 | `shortwave_radiation`、`diffuse_radiation`、`direct_normal_irradiance` | 前一小时均值，标在区间末 | 包含当前时刻的区间，即 `ceil` |
| 瞬时 | `temperature_2m`、`apparent_temperature`、`relative_humidity_2m`、各层 `wind_speed_*`、`wind_direction_10m`、`cloud_cover`、`weather_code` | 标注时刻的瞬时值 | 当前整点，即 `floor` |

由辐射推出的量（光伏逐时出力、晴空指数 kt）跟随辐射走；
由瞬时风速推出的量（风电逐时出力、强风预警）跟随瞬时值走。

实现见 `services/weather.Forecast.current_hour()` 与 `current_interval()`：

```
06:30  →  current_hour() = 06:00     气温 / 风速 / 云量
          current_interval() = 07:00  辐射 / 光伏出力 / kt
```

整点时两者相同，取到的是刚结束的完整区间。
统一用 `floor` 会拿已经过去的那一小时当「当前」：北京夏至日 06:30 的光伏出力
会报成 19 kW 而不是 84 kW，日落后一小时则反向高估。


用途：

分析太阳能资源、估算光伏发电量。

## 三、卫星遥感数据


### Himawari（葵花卫星）


主要用途：

实时云图。


基础参数：

| 项 | 值 |
| --- | --- |
| 卫星 | Himawari-9（AHI 传感器） |
| 覆盖 | 东亚 – 西太平洋全圆盘 |
| 更新频率 | 10 分钟 |
| 时间戳展示 | 预警页卫星云图左上角「2024-07-20 14:00」 |

云图走 JMA 的网页瓦片，**辐照走另一条链路**：JAXA P-Tree 的 L2 短波辐射（SWR），
由 Buffalo 上的定时任务每 10 分钟入库到自建 Open-Meteo，后端按坐标查。口径与授权见
[19 §四](./19-forecast-uncertainty-and-observations.md)。

| 项 | 值 |
| --- | --- |
| 产品 | JAXA 葵花 L2 SWR v2.1（同一文件里还有 PAR、UVA、UVB、气溶胶） |
| 分辨率 | 0.05°（约 5 km），10 分钟一帧 |
| 落地延迟 | 约 22 分钟（实测），加我们 10 分钟的拉取间隔，实况约半小时 |
| 查询 | `{自建}/archive?models=jma_jaxa_himawari&temporal_resolution=native`，**不带 native 只回小时均值** |
| 字段 | `shortwave_radiation`、`direct_radiation`、`diffuse_radiation`（后两者由 Open-Meteo 分解） |
| 出网 | 一帧约 50 MB × 144 帧/天 ≈ 7.4 GB/天，只在 Buffalo 出，不经北京 |
| 署名 | 「JAXA / P-Tree」，与云图的「日本气象厅」一样不能删 |


使用：

#### 可见光

波段：

B03（0.64 μm），空间分辨率 0.5 km。


用途：

- 白天云层观察
- 云覆盖范围


限制：

夜间无可见光信号，需自动切换至红外。

> **V1 实际落地（2026-09）：** 数据源用日本气象厅（JMA）官网的 Himawari-9 瓦片
> `www.jma.go.jp/bosai/himawari/data/satimg/{time}/fd/{time}/{band}/{z}/{x}/{y}.jpg`，
> Web Mercator XYZ，最高 z=5（约 4–5 km/px），10 分钟一帧，`targetTimes_fd.json` 给可用时刻。
> 四个产品都有：`B03/ALBD` 可见光反照率、`B13/TBB` 红外亮温、`B08/TBB` 水汽、`REP/ETC` 真彩。
> **昼夜按站点太阳高度角（> 5°）切换**：白天分析用 B03、展示用真彩；夜间分析与展示都用 B13。
> 云量强度是渲染灰度的代理，不是定量云量：可见光阈 100（晴空 p99 = 44），
> 红外阈 48（红外看不到低暖云，同图只命中约六成可见光云、误判 1%，夜间偏保守）。
> 曾用 NICT 真彩图（无红外），已弃用。JMA 瓦片是网页自用接口无 SLA，
> 正规兜底是 NOAA 开放数据 `s3://noaa-himawari9`（L1b 全波段，需自行解码投影），见 09。


#### 红外

波段：

B13（10.4 μm），空间分辨率 2 km。


用途：

- 全天云层检测
- 云顶温度分析


#### 水汽

波段：

B08（6.2 μm），空间分辨率 2 km。


用途：

- 大气湿度
- 天气变化趋势

### 卫星数据应用


用于：

#### 云层识别


判断：

当前位置是否有云。


输出：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `cloud_over_site` | bool | 站点上空是否被云覆盖 |
| `cloud_intensity` | 0–1 | 云量强度，对应预警页「云量强度」低—高图例 |


#### 云团移动


分析：

- 移动方向
- 移动速度


方法：

对相邻两帧云图做位移估计，得到云团移动矢量。

**已落地：** 站点周边 ±2.5° 重投影成 512px 等经纬度图，
相邻两帧做 Farneback 稠密光流，按梯度幅值加权取平均位移
（大片均匀云内部光流为 0，直接取中位数会严重低估）。帧间隔按实际时刻算（JMA 偶有缺帧），
超过 25 分钟不做外推。夜间用红外，也能出短临预警。实现与阈值见 [07 §四](./07-metrics.md)。


#### 短临预警


预测：

未来几十分钟云层影响。


外推输出字段（对应预警页三宫格）：

| 展示项 | 字段 | 单位 | 示例 |
| --- | --- | --- | --- |
| 云团距离 | `cloud_distance_km` | km | 80 |
| 移动方向 | `cloud_direction` | 方位文案 | 东北 |
| 移动速度 | `cloud_speed_kmh` | km/h | 内部计算，不直接展示 |
| 预计影响时间 | `impact_in_minutes` | 分钟 | 45 |
| 影响起始时刻 | `impact_start_time` | HH:mm | 14:30 |
| 预计辐射降幅 | `radiation_drop_percent` | % | 20 |

计算：

```
预计影响时间 = 云团距离 ÷ 移动速度
```

外推时效上限：120 分钟，超出不出预警。

## 四、地图图层数据规格


地图页固定 5 个图层，同一时刻仅一个数据图层激活（站点图层可与其叠加）。


### 图层总览

| 图层 | 数据源 | 数据形态 | 单位 | 更新频率 |
| --- | --- | --- | --- | --- |
| 云图 | Himawari | 卫星影像瓦片 | — | 10 分钟 |
| 风场 | Open-Meteo 网格 | 矢量场（U/V） | m/s | 1 小时 |
| 温度 | Open-Meteo 网格 | 标量场 | ℃ | 1 小时 |

| 站点 | 用户站点数据 | 点要素 | — | 实时 |


---

### 云图图层


数据：

Himawari 可见光 / 红外 / 水汽三选一，默认按当地昼夜自动切换可见光与红外。

**已落地：** 白天用可见光反照率、夜间用红外亮温，重投影为等经纬度后按波段区间
线性拉伸为强度，透明度随强度变化；卫星源不可用时退回 Open-Meteo 预报 `cloud_cover`。
两种来源共用同一套图例，`observed_at` 分别为卫星观测时刻 / 预报小时。


渲染：

栅格瓦片叠加在底图之上。


图例：

```
云量强度   低 ——————— 高
```

叠加透明度：0.75，避免完全遮挡行政边界与地名。


---

### 风场图层


数据：

网格化风速与风向。


> 注意：流线动画需要正交分量 U / V，Open-Meteo 返回的是「风速 + 风向」标量对，
> 必须在渲染前换算，否则无法绘制设计稿中的白色流线。

换算：

```
u = -wind_speed × sin(wind_direction × π / 180)

v = -wind_speed × cos(wind_direction × π / 180)
```


渲染：

- 底色：风速色阶
- 叠加：白色流线粒子动画，流线方向即风向，粒子速度正比于风速


网格：

请求分辨率 0.25°，按当前视窗范围裁剪。


---

### 温度图层


数据：

网格化 2 米气温。


渲染：

连续色阶填充。


图例：

```

-20  -10   0   10   20   30   40
```

### 辐射图层


数据：

网格化短波辐射。


渲染：

连续色阶填充。


图例（对应地图页左下角）：

```

0   200   400   600   800   1000
```

色阶方向：

```
低 蓝 → 青 → 绿 → 黄 → 橙 → 红 高
```

超过 1000 W/m² 的值按 1000 截断显示。

数据：

用户自建站点。

| 元素 | 说明 |
| --- | --- |
| Marker | 按站点类型区分图标（光伏 / 风电） |

| 项 | 规则 |

### 数据质量（2026-09-15）

体检发现目录的主要问题不是重复记录，而是占位坐标、WRI 与 GEM 重叠和合并场址命名。统一由
`app/catalog/quality.py` 处理：迁移 `7c1e4d2b9a53` 在部署时对已有库执行一次，之后每次导入与月度同步后重算。
逻辑只依赖库内字段，重复执行结果不变；原坐标、原名称、判定依据都记在溯源里，迁移可降级恢复。

| 问题 | 规模（2026-02 版） | 处理 |
| --- | --- | --- |
| 同名、同坐标、同容量的「完全重复」 | 102 组 111 条 | **不是重复**：GEM 里是不同项目（如白沟商业屋顶光伏 I–VI 期，投运年份、容量不同，中文名相同）。全目录汇总改按 GEM 分期 ID 去重，此前按名称合并会误删容量恰好相同的项目 |
| 省级占位坐标：同一坐标 ≥ 3 座且跨市 | 805 座 75.7 GW（风电 64.4 GW），28 个坐标，如内蒙古 76 座叠在 43.2443, 114.3252 | 改用同县坐标可靠场站的中位点，没有同县参照时用同市；727 座按同县、48 座按同市修正，30 座找不到参照、坐标不动且不参与发电预测（`catalog_basis`） |
| 市级占位：同一坐标 ≥ 3 座、同市跨县 | 507 座 17.2 GW | 271 座按同县修正；236 座（1.0 GW）无参照，保留市级坐标 |
| 同一坐标 ≥ 3 座、同县 | 6,787 座 70 GW | 视为县级近似，不处理 |
| WRI 与 GEM 重叠 | 1,029 条 WRI 中 927 条在 20 km 内已有同类型 GEM 容量不小于它；另有「Gansu Wind Farm 6000 MW」这类基地汇总条目 | 状态记为 `duplicate`（500 MW 以上汇总条目按 50 km 判），不出现在列表、地图与汇总；保留的 101 条取 50 km 内最近 GEM 场站的省、市，1 条附近没有 GEM 场站仍无省份 |
| 合并场址名称以英文区县开头、互相撞名 | 1,388 个合并场址；同类型重名 515 组 | 用最大一期的中文名「等 N 期」；仍重名的按英文名里的期号（I、II）或容量加后缀，处理后重名 0 组 |

同县可靠场站离中位点的距离中位 30 km、P90 155 km，修正后仍是近似位置。以 REIT 公告核对的包头华晨风电：
原坐标 43.24, 114.33（省级占位），修正为 41.28, 109.95，距公告所在乡镇约 14 km。
- 省市区：GEM 的省份映射成中文，市县暂为英文；配了腾讯 key 后回填任务逐步换成中文

  这次没出现的 GEM 条目标记 `retired`，搜索与 marker 不再显示，用户已添加的站点不动。
  每次同步都会在 GEM 那边留一条提交记录，不要把周期调得比月更短

### model-v4 日边界补充

光伏输入仍是区间末标注，但日预测响应统一改为区间起点标注；例如 12:00–13:00
使用辐射标签 13:00，预测曲线显示 12:00。瞬时风速与风电曲线仍使用整点起点。
原始气象趋势保留上游标签，不能据相同标签直接与混合功率相加。

### 2026-09 IFS HRES 地图网格升级

温度、风场、辐射固定使用 Open-Meteo AWS `data_spatial/ecmwf_ifs` 的 IFS HRES O1280
