# 02 UI 设计规范 · Design System

## 2026-09-14 移动端紧凑布局（优先于下文历史规范）

- 首页顶部使用电站名、地区／类型／容量两层信息；常规投运状态留在资料页，待核实状态直接展示。范围页签与简写模型选择并排，模型全称及起报批次在选择器和预测口径内查看。
- 预测卡按「所选日电量与峰值 → 所选日功率曲线 → 七日电量」组织，切日同时更新数字与曲线。资料入口放在卡片标题行；数据明细放在曲线标题右侧，导出仅在展开的明细区展示。刷新状态合为一行。
- 气象指标优先四列，窄屏回落两列；不重复展示日间天气评价。24 小时气象趋势默认折叠，记住本机展开偏好；全目录合计仅在「全部电站」展示。
- 首页与目录范围切换采用无阴影的下划线页签；实际点击高度至少 44px。卡内逻辑间距 8–12px，页面边距 16px，紧凑数据数字 17px，卡片圆角 12–16px。不通过统一缩小字号实现密度。
- 我的电站真实为空时只显示归属切换、空状态及一个添加按钮。加载、失败、游客、有数据但筛选无匹配各有独立状态；有列表时保留搜索、筛选和顶部添加入口。
- 底部导航与页面标题统一称「电站」。图表按单／双序列分配提示空间，重绘前清理完整画布，避免旧气泡残留。

### 同轮补充：详情、报告与管理页面

- 详情页收藏放在身份行，切站与报告、地图、编辑并排；已是当前电站时显示状态，不重复显示切站按钮。气象数值先于曲线，资料字段放后。
- 报告先给电站、日期、简明估算属性及结论，再给风险、分时依据与建议。长正文左对齐；完整时间和方法只保留一个信息入口，过期与刷新失败直接显示。
- 「我的」保留身份和常用入口，隐私、帮助、关于进入二级页；账号退出及删除流程保留明确确认。
- 可选表单区使用无嵌套卡片的折叠组件，折叠摘要反映已填参数。已有约束及校验失败对应区自动展开。底部保存栏预留安全区及内容空间，键盘出现时避免覆盖输入。
- 无预警时云图默认折叠；新预警出现时自动展开云图，风险与过期提醒不折叠。地图记住气象面板展开偏好，选中电站信息替换底部摘要，不再叠加一层浮卡；地图点击控件至少 44px。

新能源科技 + 地理信息 + AI。

## 三、字体规范


| 层级 | 字号 | 字重 | 应用 |
| --- | --- | --- | --- |
| **Hero 数字** | 40px | 800 | 每页唯一：环境指数分值。其他数字不得接近此尺寸 |
| 页面标题 | 22px | 800 | 顶栏标题（站点名 / 预警中心） |
| 模块标题 | 15px | 700 | 24小时趋势、运营建议 |
| 数据数字 | 22px | 700 | 四宫格主数值 |
| 次级数字 | 17px | 700 | 站点卡次要指标 |
| 正文 | 14px | 400 | 卡片描述、一句话结论 |
| 辅助 | 11px | 400 | 标签、时间戳、副标题 |
| 微 | 10px | 500 | 单位、环比 |

> 层级靠**尺寸差**拉开：Hero 约为四宫格数字的 1.8 倍。
> 差距不够时用户分不出主次，不要靠加边框加阴影补救。


补充规则：

- 数值与单位同行，单位字号约为数值的 35%，颜色降两级
- 所有数字用等宽数字（`tabular-nums`）并收紧字距（-0.02em），多位数才对得齐
- 千分位分隔符必须保留（2,400 / 1,008 / 6,320）
- 手写体与品牌口号不承载功能信息，**顶栏不放品牌名** —— 用户已在 app 内，
  这块位置给站点名或页面标题

## 九、布局原则


### 一页一个 Hero

每个页面只有一个视觉焦点，其余内容按「支撑 → 辅助」退后：

| 页面 | Hero | 支撑 | 辅助 |
| --- | --- | --- | --- |
| 首页 | 环境指数 | 四宫格（8px 紧贴） | 趋势、预警、入口 |
| 预警 | 当前预警标题 | 云团外推三宫格（「预计影响时间」用主色） | 云图、记录 |
| 站点 | 站点卡「今日发电」 | 其余三项（灰色次级） | 添加入口 |
| AI 报告 | 综合判断 | 今日情况 | 风险、建议、摘要 |

间距节奏：逻辑组之间 16px，组内 8px。同组卡片紧贴才读得出「这是一组」。


### 按下态

所有可点击的卡片与按钮必须有按下反馈（`scale(.985)` + `opacity .85`），
否则像静态图。小程序用 `hover-class`，H5 用 `:active`。


### 地图优先


地图相关页面：

地图占主要空间。

控件浮于地图之上，不挤压地图面积。


### 数据卡片辅助


数据使用：

卡片化展示。

同类指标固定四宫格，等宽分栏，竖线分隔。


### AI解释优先


不要只展示：

```
Cloud Cover 65%
```


转换：

```
下午云量增加，
可能影响发电效率。
```


### 数字优先


每张数据卡的视觉重心是数字本身：

```
标签（小）

数值（大）+ 单位（小）

辅助说明 / 环比（小）
```

## 2026-09 产品界面修订

本轮以目录查找效率和可信数据表达为先。公共目录采用白底、细分隔线的连续列表，名称最多两行，地区独立一行，类型与容量分开；不重复展示“查看”按钮与大色块图标。顶部搜索和类型、地区筛选保持可达，最近浏览仅存本机。

正文 14–16px，辅助说明 12–13px，关键浅灰文本改为 #64748B；图标采用 24 坐标系、1.75 描边，选中通过蓝色区分，不统一加填充。卡片圆角 12–16px。默认普通正文应达到 4.5:1 对比度。红绿仅表示有明确语义的风险与状态；气象变化方向用中性色箭头。

无设备遥测时显示“目录运营中”，不显示“设备运行正常”。无预警表示未触发规则，不能等同发电条件良好。缺测显示“—”。指数与报告提供解释、时间和估算口径。只显示可完成的操作入口。

### 2026-09-09 地图与分析阅读体验

地图图层采用独立底部选择面板，遮罩阻止底层工具误触，选择后关闭；不再沿右侧向下展开。当前电站地图标注使用短标签，完整名称放在详情入口。

发电适宜度降为辅助摘要：白底、26px 分数，等级用文字着色，说明独立一行。取消全幅等级底色与超大数字。

分析报告采用白底连续章节：电站与日期、综合判断、风险提醒、分时分析、运营建议、估算数据。元信息逐行排列，时间段采用纵向行列表，正文 14px、行高 1.7；估算指标两列，颜色集中用于风险。

站点详情优先展示完整名称、类型与容量；评分、气象趋势和当前天气各司其职。地址、坐标独立放入电站资料，不与标题挤在同一行。二级页面不预留不存在的底部 Tab 高度，只保留安全区。报告和详情的返回导航固定于顶部，避免滚动内容穿过状态栏。

### 2026-09-09 报告对齐与快捷入口补充

报告采用分区对齐：顶部电站、日期与分析口径居中；综合判断短结论居中；风险正文、分时行和运营建议仍左对齐。居中用于建立视觉焦点，不用于大段正文。快捷入口使用 22px 无填充图标、1.5 描边，统一蓝色与浅中性底色，文字 12px 中等字重；目录使用电站图形，不用设置齿轮。
# 体验收口补充（2026-09-09）

报告标题、日期和短结论居中，分时内容、建议和资料字段左对齐。图标保持细描边，扩大实际点击区域。趋势切换必须有独立加载和失败状态，不能让旧曲线冒充新指标。绝对数据时间标明北京时间，趋势横轴使用电站当地时间并说明。浏览资料不改变当前电站，切站和收藏使用显式操作。发电适宜度是气象参考，不代表设备效率或实时出力。


## 2026-09-12 紧凑化：说明进 ⓘ，一页一个 Hero

- **小字说明不铺在界面上。** 口径、假设、免责一类的解释一律收进 `InfoTip`（ⓘ 弹窗）或
  `SectionHeader` 的 `info`；界面上只留结论、数字和状态。允许留在界面的小字只有三类：
  状态（加载中、刷新失败、暂不估算及原因）、数据时间（起报、数据至、计算于）、
  署名（GEM / WRI、日本气象厅）。
- **首页一张预测卡。** 今日与未来 7 天合成一张：大数字是选中日的电量，下面 7 列横条
  （周几 / 日期 / 天气 / 竖条 / 数值 / 适宜度），再一张选中日的曲线。第 4 天起竖条变浅、
  前面一条虚线分隔，不写「中期」两个字。全目录视图同结构。
- **顶栏只留一个时间。** 模型选择器里直接显示「模型 · 起报 08:00」，卡片底部「预测计算于」，
  其余时间概念进 ⓘ。
- **上网口径按数字优先摆。** 设了出力约束的电站在大数字下方两格「预计上网 / 限电损失」，
  没有规则不出现。
- **站点页先分归属再分类型。** 顶部「公开目录 / 我的电站」两段，段内再筛光伏 / 风电；
  归属不混进类型筛选。有列表时「添加电站」收成筛选行右侧的小按钮，空态才给大入口。
- **术语。** 底部导航保留「站点」，实体一律叫「电站」，自建的叫「我的电站」。
- **表单里防错优先于解释。** 坐标系用两段开关而不是下拉；定位 / 选点后打「来自定位」标签；
  小程序内给 140 px 地图预览核对点位；容量输入框右侧实时换算 MW。
